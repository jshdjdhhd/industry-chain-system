# Frontend API Integration And Real Data Boundary Design

> 补录说明：本文按项目实际联调与数据边界调整整理，用于归档前端基础负责人的接口整合工作。

## 背景

项目开发早期存在前端 mock、参考图演示效果和真实后端能力之间边界不清的问题。为避免页面误导用户，需要统一接口调用方式，明确 mock 仅服务开发测试，真实页面以接口返回为准。

## 目标

- 梳理前端 API 调用入口和错误处理方式。
- 清理界面中容易误导用户的 mock 状态文案。
- 避免前端硬编码业务统计、企业数量或伪造消息提醒。
- 保证后端接入后页面能自然切换到真实数据。
- 处理企业管理、标签管理等页面切换时的请求异常提示。

## 非目标

- 不删除测试所需 mock 合同。
- 不在前端实现后端缺失的业务规则。
- 不用静态假数据伪装完整产品能力。

## 设计原则

- 页面展示数据必须来自接口、store 或用户操作结果。
- 开发 mock 只保留在 API mock 层和测试层，不作为正式 UI 文案出现。
- 请求失败应通过统一错误提示暴露，不吞掉异常。
- 页面统计值应动态计算，不手写固定数值。

## 涉及范围

- `src/api/*`
- `src/stores/*`
- `src/views/dashboard/DashboardView.vue`
- `src/views/enterprise/EnterpriseList.vue`
- `src/layouts/AdminLayout.vue`
- `src/components/*`

## 验收标准

- 后端模式下不显示“前端 Mock 数据”等误导状态。
- 首页、企业管理、标签管理路由切换不因前端假逻辑报错。
- 看板统计和企业列表统计按接口数据动态计算。
- 前端保留测试 mock 能力，但 UI 不把 mock 当真实业务展示。
