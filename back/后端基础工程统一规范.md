# 产业链管理系统后端基础工程统一规范

> 版本：v1.0  
> 制定日期：2026-06-25  
> 适用范围：后端工程、数据库、统一响应、异常处理、鉴权、日志、测试和接口联调  
> 依据：实训培训课件中的 Spring Boot、Spring Security、MyBatis、MyBatis-Plus 与编码规范  

## 1. 规范效力

本规范是后端编码阶段的统一实施基线。

- 后续代码、SQL、配置和接口联调必须遵循本规范。
- 若本规范与前期分析文档存在冲突，编码实现以本规范为准。
- `slides.md` 是阶段汇报材料，不作为当前编码规范。
- 修改本规范必须经后端基础负责人确认并通知全组。

每个业务模块内部按职责拆分：

```text
controller
service
service.impl
mapper
entity
dto
vo
```

分层规则：

- Controller 只负责接收参数、参数校验、调用 Service 和返回响应。
- Service 负责业务规则、状态流转和事务，不返回 `Result`。
- Mapper 只负责数据库访问，不写业务判断。
- Entity 与数据库表对应，不直接作为接口响应。
- DTO 用于接收请求，VO 用于返回页面数据。
- 超过两个业务参数时使用 DTO 或 Query 对象，禁止使用 `Map` 传递。
- 统一使用构造器注入，禁止字段注入。

## 5. 统一响应

所有 JSON 接口统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

响应对象：

```java
public class Result<T> {
    private Integer code;
    private String message;
    private T data;
}
```

统一规则：

- 成功码固定为 `200`。
- 禁止同时存在成功码 `0` 和 `200`。
- HTTP 状态码与响应体 `code` 保持一致。
- Controller 不手工拼装重复响应结构，统一调用 `Result.success()`、`Result.failure()`。
- 文件下载接口直接写入 `HttpServletResponse`，不套 `Result`。

错误码：

| HTTP/code | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 请求参数错误或一般业务规则不允许 |
| 401 | 未登录、Token 缺失、Token 无效或已过期 |
| 403 | 已认证但没有访问权限 |
| 404 | 请求的业务资源不存在 |
| 409 | 唯一数据冲突或重复绑定 |
| 500 | 未预期的系统内部错误 |

业务异常必须返回用户可理解的信息，禁止把 SQL、堆栈和服务器路径返回前端。

## 6. 分页规范

请求参数统一为：

```text
pageNum：页码，从 1 开始，默认 1
pageSize：每页条数，默认 10，最大 100
```

响应格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [],
    "total": 0,
    "pageNum": 1,
    "pageSize": 10
  }
}
```

禁止混用：

- `page` 与 `pageNum`
- `list` 与 `records`
- `size` 与 `pageSize`

分页由 MyBatis-Plus `PaginationInnerInterceptor` 实现。查询总数为 0 时直接返回空分页结果。

## 7. 参数校验与异常处理

请求 DTO 使用 Jakarta Validation：

```java
public class LoginRequest {
    @NotBlank(message = "用户名不能为空")
    private String username;

    @NotBlank(message = "密码不能为空")
    private String password;
}
```

Controller 参数必须加 `@Valid` 或 `@Validated`。

全局异常处理至少覆盖：

- `MethodArgumentNotValidException`
- `ConstraintViolationException`
- `HttpMessageNotReadableException`
- `BusinessException`
- `AccessDeniedException`
- 未知 `Exception`

规则：

- 可以预检查避免的异常，不使用 `try-catch` 作为流程控制。
- 禁止吞掉异常。
- 事务方法捕获异常后仍需回滚时，必须重新抛出或显式回滚。
- 未知异常统一记录完整堆栈，对外返回 500 和通用提示。
- 禁止在 `finally` 中返回结果。

## 8. 数据库规范

### 8.1 基础配置

- 数据库版本固定为 MySQL 5.7。
- 存储引擎统一使用 InnoDB。
- 字符集统一使用 `utf8mb4`。
- 排序规则统一使用 `utf8mb4_general_ci`。
- 不使用 MySQL 8 专属的递归 CTE、窗口函数、`JSON_TABLE` 等语法。
- 树形数据通过 `parent_id`、`node_path` 和后端组装完成。

### 8.2 公共字段

所有业务表统一使用：

```sql
id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
    ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
is_deleted TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '删除标识：0-未删除，1-已删除',
PRIMARY KEY (id)
```

禁止混用：

- `created_at` 与 `create_time`
- `updated_at` 与 `update_time`
- `deleted` 与 `is_deleted`

Java Entity 中逻辑删除属性命名为 `deleted`，通过注解映射数据库字段：

```java
@TableLogic
@TableField("is_deleted")
private Integer deleted;
```

### 8.3 字段与索引

- 表名、字段名使用小写下划线，表名使用单数。
- 金额、税收、产值和置信度使用 `DECIMAL`，禁止使用 `FLOAT`、`DOUBLE`。
- 固定长度编码优先使用 `CHAR`，普通文本使用 `VARCHAR`，长文本使用 `TEXT`。
- 表和字段必须写 `COMMENT`。
- 业务唯一字段必须建立唯一索引。
- 关联字段和高频查询字段必须建立普通索引。
- 主键名使用 `pk_字段名`，唯一索引使用 `uk_字段名`，普通索引使用 `idx_字段名`。
- 不建立数据库外键，不使用级联更新或级联删除，引用完整性由 Service 保证。
- 不使用存储过程。
- 所有删除使用逻辑删除，历史关系按业务要求保留。

### 8.4 SQL 规则

- 参数必须使用 `#{}`，禁止使用 `${}` 拼接用户输入。
- 自定义查询明确列出字段，禁止 `SELECT *`。
- 多表查询中的字段必须带表别名。
- 单条 SQL 原则上不超过三个表 JOIN。
- 使用 `COUNT(*)` 统计行数。
- 使用 `IFNULL(SUM(column), 0)` 避免空值。
- 页面搜索不得使用左模糊；确需包含搜索时须明确评估数据量。
- `IN` 集合控制在 1000 条以内。
- 更新记录必须同步维护 `update_time`。

## 9. MyBatis 与 MyBatis-Plus 规范

统一以 MyBatis-Plus 为基础：

- 单表常规 CRUD 使用 `BaseMapper` 和 `IService`。
- 条件查询优先使用 `LambdaQueryWrapper`、`LambdaUpdateWrapper`。
- 分页使用 MyBatis-Plus 分页插件。
- 逻辑删除使用 `@TableLogic`。
- 创建时间、更新时间使用自动填充或数据库默认值，项目中只能选择一种方式统一执行。
- 多表查询、树形统计、复杂动态查询使用 Mapper XML。
- Mapper XML 的 `namespace` 必须是 Mapper 接口全限定名。
- XML 中语句 `id` 必须与 Mapper 方法名一致。
- 复杂结果必须定义 `resultMap`，禁止使用 `HashMap` 接收业务查询结果。
- 不使用 ActiveRecord 模式。
- 不默认开启 MyBatis 二级缓存。

MyBatis 配置：

```yaml
mybatis-plus:
  mapper-locations: classpath*:/mapper/**/*.xml
  configuration:
    map-underscore-to-camel-case: true
  global-config:
    db-config:
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0
```

生产配置禁止开启控制台 SQL 输出；开发环境可按需开启。

## 10. 鉴权规范

### 10.1 总体方案

第一版统一采用：

```text
Spring Security + JWT + MySQL 用户权限数据
```

- 使用无状态会话，`SessionCreationPolicy.STATELESS`。
- 第一版不强制引入 Redis。
- 禁止使用课件中“任意非空 X-Token 即视为 admin”的演示逻辑。
- Token 中至少包含用户 ID、用户名、签发时间和过期时间。
- 权限信息以数据库当前状态为准，不在代码中写死。

### 10.2 Token 协议

请求头统一为：

```http
Authorization: Bearer <token>
```

禁止使用自定义 `X-Token`。

JWT 有效期统一为 2 小时。密钥通过环境变量配置：

```yaml
security:
  jwt:
    secret: ${JWT_SECRET}
    expiration: 7200
```

JWT 密钥、数据库密码等敏感信息禁止提交到 Git。

### 10.3 鉴权接口

统一接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | 用户登录并返回 Token |
| POST | `/api/auth/logout` | 前端清除 Token，后端返回成功 |
| GET | `/api/auth/me` | 获取当前登录用户及权限 |
| GET | `/api/health` | 健康检查 |

匿名放行：

- `/api/auth/login`
- `/api/health`
- smart-doc 生成的静态文档资源（仅开发环境）

其他 `/api/**` 接口默认要求认证。

### 10.4 密码与用户状态

- 数据库只存储 BCrypt 编码结果，禁止存储明文密码。
- 使用 `PasswordEncoderFactories.createDelegatingPasswordEncoder()`。
- 密码格式使用 `{bcrypt}` 前缀。
- 登录时检查用户是否存在、是否删除、是否停用、是否锁定、账号是否过期。
- 登录失败统一提示“用户名或密码错误”，不泄露账号是否存在。

### 10.5 授权

- 开启 `@EnableMethodSecurity`。
- 需要权限的业务方法或 Controller 使用 `@PreAuthorize`。
- 权限编码使用 `模块:资源:动作`，例如：

```text
enterprise:enterprise:query
enterprise:enterprise:update
chain:node:query
chain:node:update
matching:task:execute
```

- 401 由 `AuthenticationEntryPoint` 统一返回。
- 403 由 `AccessDeniedHandler` 统一返回。
- 用户只能访问权限范围内的数据，禁止仅凭前端隐藏按钮实现权限控制。

### 10.6 Security 配置

- JWT 过滤器继承 `OncePerRequestFilter`。
- Token 校验成功后才能写入 `SecurityContext`。
- JWT 过滤器放在 `UsernamePasswordAuthenticationFilter` 之前。
- 前后端分离且使用 Bearer Token 时关闭表单登录和 HTTP Basic。
- CSRF 仅在无状态 Bearer Token 模式下关闭。
- CORS 只允许配置中的前端地址，不使用无限制通配。

## 11. 日志与操作审计

- 使用 `logback-spring.xml` 配置日志。
- Java 代码通过 SLF4J 输出日志，可使用 Lombok `@Slf4j`。
- 禁止 `System.out.println`、`System.err.println` 和 `printStackTrace()`。
- 日志参数使用 `{}` 占位符，不使用字符串拼接。
- 异常日志同时记录业务上下文和完整异常堆栈。
- 禁止记录密码、完整 Token、JWT 密钥和数据库密码。
- 用户敏感信息需脱敏。
- 登录、企业入库/出库、节点变更、挂链/解绑、推荐采纳/拒绝必须记录操作日志。
- 操作日志建议通过自定义注解和 AOP 统一实现。

## 12. 接口与文件处理

- REST Controller 使用 `@RestController`。
- 查询使用 GET，新增使用 POST，修改使用 PUT，删除使用 DELETE。
- 业务动作可使用 POST，例如 `/api/enterprises/{id}/inbound`。
- 文件上传使用 `multipart/form-data`，参数名统一为 `file`。
- 上传文件必须校验扩展名、MIME 类型和文件大小。
- 文件路径使用 `Path` 或 `File.separator`，禁止硬编码操作系统分隔符。
- 下载接口必须设置正确的 Content-Type 和 Content-Disposition。

接口文档使用 smart-doc 根据 JavaDoc 生成：

- Controller、DTO、VO 和公共响应对象必须编写 JavaDoc。
- 接口变更必须同步更新 JavaDoc 并重新生成文档。
- 生产环境不部署接口文档生成能力。

## 13. 配置管理

配置文件按环境拆分：

```text
application.yml
application-dev.yml
application-test.yml
application-prod.yml
```

`application.yml` 只保存公共配置，通过：

```yaml
spring:
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:dev}
```

激活环境。

本地密码和密钥放在环境变量或不提交 Git 的本地配置中。禁止在仓库中出现：

- 数据库真实密码
- JWT 密钥
- 外部模型 API Key
- 个人绝对路径
- 共享服务器凭据

## 14. 事务规范

以下操作必须在 Service 层使用 `@Transactional(rollbackFor = Exception.class)`：

- 企业批量导入、批量出库。
- 企业与标签绑定或解绑并记录日志。
- 节点新增后维护 `node_path`。
- 节点删除校验与逻辑删除。
- 企业挂链和解绑。
- 采纳推荐：更新推荐结果、创建挂链关系、写操作日志。

事务方法必须是可被 Spring 代理的 `public` 方法。禁止在同一个类中通过 `this` 调用事务方法。

## 15. 测试规范

- 测试类放在 `src/test/java`。
- 测试类命名为 `被测类名 + Test`。
- 使用 JUnit 5 断言，禁止通过控制台输出人工判断。
- 单元测试必须自动化、独立、可重复执行。
- Service 单元测试使用 Mockito 隔离 Mapper 等外部依赖。
- Controller 使用 MockMvc 验证状态码和统一响应格式。
- Security 测试至少覆盖匿名访问、登录成功、Token 缺失、Token 失效、无权限访问。
- 核心业务必须覆盖正确流程、边界值和异常流程。

提交前统一执行：

```bash
mvn test
mvn package
```

## 16. 编码约束

- 类名使用 UpperCamelCase，方法和变量使用 lowerCamelCase。
- 常量使用大写下划线。
- 包名全部小写。
- 使用 4 个空格缩进，禁止 Tab。
- 单行不超过 120 个字符。
- 禁止魔法值，状态值使用枚举或常量。
- `BigDecimal` 使用字符串构造或 `BigDecimal.valueOf()`。
- 禁止返回 Entity，接口只返回 VO。
- 禁止 Controller 直接调用 Mapper。
- 禁止 Service 返回 `Result`。
- 禁止使用通用大而全的更新接口修改所有字段。
- 涉及多表写入必须使用事务。
- 关键接口必须有参数校验、异常处理和日志。
