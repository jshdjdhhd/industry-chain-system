## 一、当前状态分析

### 布局结构（MatchingTask.vue）

当前单企业 Tab 采用 **三列网格布局**（`.matching-workbench`）：

```
┌─────────────┬──────────────────┬──────────────────┐
│  企业信息    │  候选节点列表     │  推荐理由/分析    │
│  (0.9fr)    │  (1.25fr)        │  (1.1fr)         │
└─────────────┴──────────────────┴──────────────────┘
┌──────────────────────────────────────────────────┐
│  操作日志表格（全宽）                               │
└──────────────────────────────────────────────────┘
```

### 样式特征
- 配色：蓝色主调 `#1f6fff`，浅灰背景 `#f7faff`
- 卡片：`.surface` 圆角白底 + 轻阴影
- 候选节点：列表项带 radio 指示器 + 置信度进度条
- 分析结果：`el-alert` 组件展示建议和评估
- 操作日志：`el-table` 带 expand 行展示详情

### 已有的 UI 模式（AdminLayout）
- 顶部导航栏：深蓝渐变 `linear-gradient(90deg, #092656, #0c4997, #08bfd3)`
- 侧边栏：毛玻璃白底 `backdrop-filter: blur(20px)`
- 主内容区：浅蓝渐变背景

## 二、操作日志独立方案

### 路由设计

在侧边栏 `sideGroups` 的 `matching` 分组下新增子项：

```typescript
{
  index: "matching",
  label: "智能挂链",
  icon: Connection,
  children: [
    { path: "/matching", label: "智能推荐", icon: Connection },
    { path: "/matching/logs", label: "操作日志", icon: DataLine },  // 新增
  ],
}
```

### 路由配置（router/index.ts）

新增路由：

```typescript
{
  path: "/matching/logs",
  name: "MatchingLogs",
  component: () => import("@/views/matching/MatchingLogs.vue"),
  meta: { title: "操作日志", requiresAuth: true },
}
```

### 新组件：MatchingLogs.vue

从 MatchingTask.vue 中抽取操作日志逻辑，创建独立页面：

```
┌──────────────────────────────────────────────────┐
│  操作日志                                          │
│  查看智能挂链系统的所有操作记录                       │
├──────────────────────────────────────────────────┤
│  [筛选：企业/产业链/操作类型/时间范围] [搜索] [导出]  │
├──────────────────────────────────────────────────┤
│  el-table 全功能日志表格                            │
│  - 时间 | 操作人 | 操作类型 | 操作内容 | 结果 | 操作 │
│  - expand 行展示详情                               │
│  - 分页                                           │
└──────────────────────────────────────────────────┘
```

**关键功能：**
- 筛选：按企业、产业链、操作类型（AI分析/人工挂链/批量推荐）、时间范围
- 搜索：关键词搜索操作内容
- 分页：支持大量日志的分页加载
- 撤回：保留撤回操作（对已采纳/人工确认的结果）
- 导出：导出日志为 CSV/Excel

### MatchingTask.vue 中的操作日志处理

从 MatchingTask.vue 中移除操作日志 section（`.operation-log` 部分），改为：
- 页面底部只保留一个「查看操作日志」链接，跳转到 `/matching/logs`
- 或者完全移除，靠侧边栏入口进入

### 数据源

操作日志数据来自两个地方：
1. **后端操作日志 API**（`/api/operation-logs`）— 已有的系统级操作日志
2. **前端构建的日志**（`buildMatchingOperationLogs`）— 当前会话的任务和挂链记录

独立页面应优先使用后端 API 加载历史日志，当前会话的实时日志可作为补充展示。

## 三、AI 分析模块样式重构方向

### 设计原则

1. **AI 感**：让用户一眼看出这是 AI 驱动的分析，不是传统表单
2. **渐进式**：分析过程中有明确的状态反馈（加载 → 分析中 → 结果）
3. **可读性**：分析结果以结构化、易读的方式呈现，不是堆砌文本

### 布局重构方案

### 样式方案（深色科技风）

**配色方案：**
- 背景：深蓝黑 `#0a0f1e` → `#111827` 渐变
- 卡片：`rgba(255,255,255,0.04)` 半透明白 + `border: 1px solid rgba(255,255,255,0.08)`
- 主色：电光蓝 `#3b82f6` + 渐变到 `#06b6d4`
- 强调：AI 紫 `#8b5cf6`
- 文字：`#e2e8f0`（主）、`#94a3b8`（次）
- 成功：`#10b981`、警告：`#f59e0b`、危险：`#ef4444`

**AI 分析卡片样式：**
- 带呼吸动画的边框光效（`@keyframes glow`）
- 分析中状态：流光进度条 + 脉冲动画
- 结果出现：渐入动画 `fadeInUp`
- 置信度：环形进度条替代线性进度条

**候选节点卡片：**
- 去掉列表式 radio，改为 **卡片网格**
- 每个节点是一张小卡片，高置信度的带发光边框
- 点击展开详情，不再是左右分栏

**分析建议区域：**
- 用 `el-timeline` 或自定义时间线展示分析过程
- AI 建议用特殊样式的 callout（左边框渐变色 + 背景微光）
- 风险提示用警告色卡片，带图标

### 样式方案（浅色卡片风）

如果选择保持与系统一致的浅色调：

**布局调整：**
- 三列改为 **左侧宽面板（企业画像+候选节点） + 右侧面板（AI分析结果）**
- 企业画像改为顶部横向信息条，不占一整列
- 候选节点改为 **标签云** 或 **卡片网格**，不再是列表

**关键差异点：**
- AI 分析区域用渐变色背景卡片（蓝紫渐变，与普通白色卡片区分）
- 分析中状态用 skeleton loading + 进度指示
- 结果卡片带 AI 图标标记，区别于普通内容

## 五、交互细节

### 分析流程状态机

```
[空闲] → 点击「开始分析」 → [分析中]
  ├─ 超时 → [超时] → 可重试
  ├─ 失败 → [失败] → 可重试
  └─ 成功 → [结果展示]
       ├─ 采纳 → 更新状态
       ├─ 拒绝 → 更新状态
       └─ 人工改选 → 弹窗确认
```

### 分析中状态设计

- 按钮变为 loading 状态，文字改为「分析中...」
- 工作台区域显示 skeleton loading
- 如果超过 30 秒，显示「大模型正在深度分析，请耐心等待」
- 如果超过 90 秒（前端超时），显示超时提示，可取消或继续等待

### 候选节点交互

- 默认展开置信度最高的节点
- 点击节点卡片展开/折叠详情
- 已处理的节点（采纳/拒绝）带状态标记
- 低置信度节点带警告样式

## 六、注意事项

1. **批量挂链 Tab 不改**：只有单企业 Tab 和操作日志需要重构，批量 Tab 保持现有样式
2. **API 不变**：前端重构不涉及后端 API 变更，只是 UI 层面的重新组织
3. **响应式**：新布局需要支持移动端（< 980px）降级为单列
4. **测试**：MatchingTask.spec.ts 和 matchingViewModel.spec.ts 需要同步更新
5. **操作日志数据源**：独立页面应调用后端操作日志 API，不是只展示前端构建的日志
