# 智能挂链 V2.1 改动说明

## 背景

V2 已经完成本地 Ollama + `qwen3-embedding:0.6b` 的语义挂链能力，通过企业画像和节点画像生成 embedding，再融合 V1 规则分数输出推荐结果。

V2.1 的目标不是更换模型，而是把 V2 做得更像一个可持续优化的推荐系统：领域词可维护、画像输入更干净、推荐效果可以离线评估。

## 改动范围

本次仍然只改后端智能挂链相关代码，未修改前端。

主要改动包括：

- 新增产业领域词扩展表 `industry_term_alias`。
- 新增数据库优先的领域词扩展服务 `DomainTermExpansionService`。
- 优化 `EmbeddingProfileTextBuilder`，增加字段权重提示、噪声清洗、关键词去重和长度截断。
- 新增评估样本表 `matching_evaluation_sample`。
- 新增离线评估服务 `MatchingEvaluationService`，计算 `Recall@K`、`Top1 Accuracy` 和 `MRR`。
- 补充 V2.1 单元测试与测试库 schema。

## 核心实现

### 1. 领域词库表

V2 中领域扩展词主要写在代码里。V2.1 新增 `industry_term_alias` 表，把高频企业简称、品牌词、行业词和扩展词沉淀到数据库。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `source_term` | 原始词，例如「中际旭创」「苹果」「宁德时代」。 |
| `expanded_terms` | 扩展词，多个词用逗号分隔。 |
| `industry` | 所属行业，便于后续维护。 |
| `priority` | 优先级，值越大越优先。 |
| `enabled` | 是否启用。 |
| `is_deleted` | 逻辑删除标记。 |

V6 迁移会初始化部分高频词，例如：

- 中际旭创 -> 光模块、高速光模块、光通信、光器件；
- 苹果 -> 手机、智能手机、iPhone、消费电子；
- 宁德时代 -> 动力电池、锂电池、电芯、电池模组；
- 小米 -> 智能手机、消费电子、IoT 终端、智能硬件。

### 2. 数据库优先的领域词扩展

新增 `DomainTermExpander` 接口和 `DomainTermExpansionService`。

扩展流程：

```text
输入企业/节点画像文本
        ↓
先使用本地内置领域词做兜底扩展
        ↓
读取 industry_term_alias 中启用的词库
        ↓
命中 source_term 后追加 expanded_terms
        ↓
去重并输出领域扩展词
```

这样做的好处是：

- 本地内置词保证服务没有词库数据时仍能工作；
- 数据库词库支持后续人工维护，不需要每次改代码；
- 扩展词会进入 embedding 输入画像，提高短词和企业简称的语义稳定性。

### 3. 画像文本优化

`EmbeddingProfileTextBuilder` 做了 3 个优化：

1. 增加字段权重提示，让 embedding 输入更明确。
2. 对经营范围、节点定义等长文本做空白清洗和长度截断。
3. 对主营产品、企业标签、节点关键词做分隔符统一、去重和数量限制。

企业画像中新增：

```text
字段权重提示：主营产品和核心技术优先，经营范围作为辅助语义。
```

节点画像中新增：

```text
字段权重提示：节点路径和节点关键词优先，节点定义用于补充覆盖边界。
```

这解决了 V2 中「画像文本可能过长、经营范围噪声过多、关键词重复」的问题。

### 4. 离线评估样本和指标

新增 `matching_evaluation_sample` 表，用来保存人工标注样本。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `enterprise_id` | 待评估企业 ID。 |
| `chain_id` | 所属产业链 ID。 |
| `expected_node_id` | 人工标注的正确节点 ID。 |
| `sample_name` | 样本名称，便于阅读。 |
| `reason` | 人工标注理由。 |
| `enabled` | 是否启用。 |

新增 `MatchingEvaluationService`，基于启用样本调用当前 `MatchingProvider`，并计算：

- `Recall@K`：正确节点是否出现在前 K 个推荐结果中；
- `Top1 Accuracy`：第一名是否就是正确节点；
- `MRR`：正确节点排名越靠前，分数越高；
- `misses`：记录未命中的样本，方便排查。

这一步让 V2.1 具备「可评估」能力。以后调权重、改词库、换模型，不再只凭感觉，而是可以看指标变化。

## 面试可讲版本

V2.1 不是继续堆模型，而是补齐推荐系统工程化能力。我做了三件事：第一，把领域词扩展从纯代码内置升级为数据库词库，支持后续人工维护；第二，优化 embedding 输入画像，对经营范围等长文本做清洗截断，对关键词做去重，并加入字段权重提示；第三，新增评估样本表和评估服务，用 `Recall@K`、`Top1 Accuracy`、`MRR` 衡量推荐效果。这样后续无论是调权重、改词库还是换 embedding 模型，都可以基于指标评估，而不是凭主观感觉判断。

## 后续方向

- 给评估服务补一个后端接口，方便本地或管理端触发评估。
- 增加向量预热任务，提前生成节点向量。
- 将词库维护能力接入后台管理。
- 用评估指标对 `vector_weight` 和 `rule_weight` 做参数搜索。
- V3 在 V2.1 的 Top K 结果基础上接入大模型 rerank。
